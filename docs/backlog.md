## 跨项硬约束

这几条适用于下面所有提案，动手前先读。

1. **变体预算：每个新组件首批 ≤ 4 个变体**，且每个变体都要能说清「和既有的哪个不同」。现有 4 个控件已有约 34 个视觉变体（Clock 10、AlbumArt 11、Spectrum 9、AmbientFx 7），CSS 合计 1900+ 行（`Clock.css` 833、`AlbumArt.css` 1074）。四个提案按原样实现是 24 个新变体，维护面接近翻倍；按本文件的取舍砍完是 11 个。
2. **不建共享样式表。** 表面样式由组件自己 import 重复一遍，这是既有约定（见 `AGENTS.md`）。所以变体数量直接等于维护成本，不能靠抽象摊薄。
3. **新组件三件套**：`package.json` 的 `exports` 加条目 + `src/components/index.js` 加 re-export + 组件目录。`exports` 是封闭映射，少一步使用方就 import 不到。
4. **`theme` 语义照抄**：`'light'` = 浅色文字，`'dark'` = 深色文字，默认 `'dark'`。`color` 覆盖、`visible`、`anchor` / `offsetX` / `offsetY` 也照抄，不自创。
5. **每个新组件要一个 playground 画廊页。** `playground/wallpaper.html` 的 8 秒轮换只挂 4 个控件，不会自动容纳新组件；按 `layout.html` 的模式单独做一页几何验证。
6. **CHANGELOG 补一条**「日期 + commit 短哈希」，面向使用方写能力变化。

## 1. Calendar

**结论：做。四个提案里唯一推荐正式占名额的。** 优先级中低。

### 为什么

- 四个里唯一有**真实计算**的：月网格首日偏移、跨月补位、今日高亮索引、窄星期表头。
- 与 Clock 天然互补，且**不完全重复**：Clock 的 `stamp` 只给「月日 + 年内天数 / 周数」，没有网格。
- 与既有约定零冲突：`now` 由使用方传、不内置定时器（暂停即停）、月份名与星期名走 `labels.locale` + `Intl`、不内置语言包。不切月 = 不加 state，天然满足「只展示」。

### 接口草案

| prop | 类型 | 说明 |
|---|---|---|
| `now` | `Date` | **必选**，使用方驱动 |
| `variant` | `'month' \| 'grid' \| 'date' \| 'strip'` | 默认 `'month'` |
| `miniGrid` | `boolean` | 仅 `date` 变体有效：大日期旁是否带迷你网格 |
| `note` | `string` | 应用层自备的一行补充信息（农历、节气、纪念日），**库内不计算** |
| `labels` | `{ locale, aria, monthNames?, weekdays? }` | 覆盖 `Intl` 的输出，其余同 Clock |
| `theme` / `color` / `size` / `anchor` / `offsetX` / `offsetY` / `visible` | 同 Clock | 不自创 |

### 变体取舍

| 提案中的样式 | 处理 |
|---|---|
| 标准月历卡片 | 保留 → `month` |
| 紧凑网格 | 保留 → `grid` |
| 极简日期 / 装饰性大日期 | **合并** → `date` + `miniGrid` 开关，两者只差有没有迷你网格 |
| 条状 | 保留 → `strip` |
| 记录卡（年内天数 / 周数） | **删** —— 与 Clock `stamp` 完全撞车，且 stamp 已经在用 `calendarPosition()` |

### 需要新增

- `src/core/calendar.js`：月网格纯函数（首日偏移、补位、今日索引、`Intl` 窄星期表头），约 100 行，可单测。
- 复用 `core/clock.js` 的 `calendarPosition()`（年内第几天 / ISO 周数）与 `formatClockDateParts()`，不重写。
- `src/components/calendar/{index.js, Calendar.jsx, Calendar.css}`。
- playground 画廊页。

### 不做的部分

农历 / 节气**不作为计算能力内置**——那需要一张年表或换算算法，属于数据不是展示。要显示就走 `note` 一条字符串由应用层决定。

估算：JSX ~150 行 + CSS ~250 行。

## 2. Frame / Decoration

**结论：做，但动手前必须先定「它是不是布局容器」。** 优先级低。

### 为什么

- 成本最低、观感收益最直接：可能零 JS 逻辑，纯 CSS 伪元素。是这个库里「每行代码换来的观感」最高的一项。
- 但它的功能边界自相矛盾：声明「不承担布局容器职责」，又必须相对某个控件摆放。

### 待定的定位契约（动手前必须先决定）

| 方案 | 做法 | 代价 |
|---|---|---|
| A. 独立装饰层 | 自带 `anchor` / `offset` / 尺寸，使用方自己把 Clock 放在同一区域 | 库内一致，但要手调两套数字，容易错位 |
| B. 受限包裹层 | `position: relative` 包裹 + 绝对定位的装饰，**不参与尺寸计算、不改子元素布局**（内边距由使用方给） | 违反「不是布局容器」的字面表述，需要改写这条边界 |

**倾向 B。** 附带好处：装饰靠 DOM 顺序就压在子元素下面，不用动 `z-index` 层级链（ambient 1 → spectrum 3 → pointer 4 → clock/album 5 → spotlight 6）；方案 A 则要往链里插一层 2。

若选 B，`AGENTS.md` 里的表述应改为「**装饰容器**，不是布局容器」——它包裹、只画装饰、不排版。

### 变体取舍

首批 4 个：`line`（线框）/ `corners`（角饰）/ `bracket`（翼型括号）/ `glow`（柔光底托）。

| 提案中的样式 | 处理 |
|---|---|
| 分割线 | **独立**为 `Divider`，或降为 `rule` 变体 —— 它没有 wrapper 语义，跟「框」不是一类 |
| 印章式边框 / 科技切割边 | 第二批 —— 需要裁切或 SVG，成本明显高于其余四个 |

估算：JSX ~60 行 + CSS ~200 行。

## 3. InfoCard / Status

**结论：可做，但必须限死数据形状，否则会烂成万能面板。** 优先级很低。

### 为什么

- 分层上完全兼容（纯 props、不采集、不轮询），实现风险在四个里最低。
- 真风险不是技术，是**它会变成任意内容的容器**：一旦接受 `children` 或富内容，每个壁纸都会长出不同用法，库就失去了接口意义。
- 顺带提一句：[§15](./architecture.md#15-与原方案的差异) 里原方案的 `weather` 组件已被否决，理由正是「无实现基础」。InfoCard 想显示天气，数据只能由应用层采集后当字符串传进来，这必须在文档里写死。

### 接口草案

| prop | 类型 | 说明 |
|---|---|---|
| `items` | `Array<{ label?: string, value: string, tone?: 'normal' \| 'accent' \| 'muted' }>` | **必选**，纯字符串 |
| `title` | `string` | 可选组标题 |
| `variant` | `'card' \| 'strip' \| 'plain'` | 默认 `'strip'`；v1 只实现 `strip` / `plain` |
| `layout` | `'rows' \| 'pills'` | 同一份 DOM 的排布差异，不单列变体 |
| 其余 | 同 Clock | — |

### 明确不做

- 不接受 `ReactNode`、不接受图标。
- 不提供点击、展开、编辑。
- 不做轮播、不做复杂动画。

### 变体取舍

5 → 3（v1 实际只做 2 个）：`pills` 与 `stack` 本质是同一份 DOM 的排布差异，收进 `layout`；`card` 与 Clock `card` / `infobar` 观感接近，先不做——它自己的定位就是「低存在感、不抢主视觉」，那正好对应 `strip` / `plain`。

估算：JSX ~80 行 + CSS ~180 行。

## 4. Text / Quote

**结论：暂不进库，留在应用层。** 优先级：不排。

### 为什么

- 没有数据形状、没有计算，只有一个 `text` prop 和若干 class，本质是「一段文字 + 一套排版预设」。
- 这正是 §12.3 描述的情形：「只在这一个游戏用 → 留在该游戏仓库」，而且它连一次都还没用过，没有证据。
- 最实际的理由：它最容易把已被明确排除的东西带回来——轮换句、打字机、富文本、复制按钮。一旦进库，后续需求都会往这个口子挤，每一条都和「只展示给定文本」打架。

### 触发条件

应用层里手写过第二遍同样的样式，再谈提升。

### 如果将来真要做

只做 2 个：`quote`（引号 + 来源）/ `plain`（大字与说明两档）。提案里的 `terminal` 与 Clock `cyberpunk` 同气质、`大字报` 与 Clock `poster` 同气质，属于重复投资。
